# dogfood：每天用 codelotte 干真实开发任务

> 从 2026-10-18（票据 14）起，用 codelotte 做真实开发，而不是只跑演示。
> 目标：累积「连续使用 N 天、合并 M 个自产 PR、省时 / 翻车 / 成本」的面试素材。
> **状态（2026-10-19）**：仍为 **0 条记录 / 0 天 / 0 个自产 PR**。票据 14 的连续记录
> 暂时忽略，作者后续补充；表结构已就绪，从补充当天开始逐条填写。
> 面试材料不把 dogfood 写成已完成成果（见 [interview/resume.md](../../interview/resume.md)）。
> 记录表：[log.md](log.md)。

## 什么算一条记录

- **真实任务**：改这个仓库或另一个真实项目；有明确的完成标准。
- **不是演示**：不要为了凑数跑 `evals/tasks` 里的题（那是评测，不是 dogfood）。
- **失败也记**：卡住、放弃、改回人工，都算数据；失败比成功更能讲出问题。
- **一个任务一行**：中途拆成多个独立任务就记多行。

## 记录什么

| 列 | 含义 |
|---|---|
| Date | 日期（`YYYY-MM-DD`） |
| Task | 一句话任务；必要时带文件/模块 |
| Mode | `TUI` / `-p` / `--continue`；是否 `--no-sandbox` |
| Result | `done` / `partial` / `failed` / `abandoned` |
| Duration | 墙钟时间（分钟）；只记 agent 实际工作的时间 |
| Cost (CNY) | 会话账单合计；`-p` 退出时打印，TUI 看状态栏/账单 |
| Incidents | 翻车点：权限拒绝、工具失败、循环、压缩后失忆、模型误判；没有写 `—` |
| Session | 会话文件路径或导出的 HTML；至少写会话文件名 |
| Notes | 复盘：为什么发生、是否已修、下一步 |

## 示例（格式示意，不是真实数据）

```markdown
| YYYY-MM-DD | 一句话任务（带文件/模块） | `-p` | done | 12 | 0.08 | 工具失败一次，换方法成功 | `~/.codelotte/sessions/.../<时间>_<id>.jsonl` | 复盘一句话 |
```

## 怎么拿到数据

- **成本**：`-p` 结束打印「账单（会话累计）」；TUI 退出时同样打印；会话 JSONL 里每次
  `usage` 都有 `cost`。
- **会话路径**：`-p` 最后一行打印；TUI 在成本面板附近；也可以 `codelotte --resume` 列表看。
- **导出**：在会话发生的工作目录执行 `codelotte export --html`，把链接一起记下来。
- **耗时**：开始任务时看一眼时钟，或使用终端计时的 shell 函数；不要事后估算。

## 每周复盘（周日 10 分钟）

1. 数：任务数、`done` 比例、总成本、平均耗时。
2. 挑：出现 ≥2 次的翻车模式，记进 Issues / 票据。
3. 问：有没有任务本可以不用 agent？有没有因为权限/沙箱卡住的真实工作？
4. 更新：把最典型的 1 条轨迹导出 HTML，作为面试讲解素材。

## 记录纪律

- **不编数据**：没有跑就不写；估算值标注 `~`。
- **不写密钥/隐私**：会话路径里的用户名可以保留，但不要把 API key、公司代码粘进来。
- **当天写**：隔天回忆会漏掉翻车点；成本也会对不上。
- **连续天数**：以 `log.md` 中不重复的日期数为准；中断一天就重新数，别改历史。

# Roadmap

> 这是方向，不是承诺。没有日期；优先级按「证据缺口 → 面试价值 → 维护成本」排。
> 当前版本：**0.1.1（2026-10-19）**，票据 01–22 均已标记 done；
> 其中录屏、dogfood 连续记录、整场口述计时是作者待补项。
> 最近更新：2026-10-19。

## 现在有什么

- **可测量的 harness**：四工具 minimal core、append-only 会话树、双触发压缩、
  权限层 + Docker 沙箱、死循环三层防御、逐次成本记账、HTML/Markdown 导出。
- **评测闭环**：9 条通用任务（A/B 桶，含压缩回归 001–003 与注入 004/005）、3 条 judge 任务、
  3 条独立注入任务、1 条死循环压力任务；
  `eval run / compaction / compare / controls / judge / attribute / regression / cost / defense`
  九个命令；pass^k、控制 agent 自检、κ 校准、失败归因与回归任务。
- **五组实验**：E1 压缩曲线、E2 成本曲线、E3 归因准确率、E4 scaffolding tax、
  E5 防御有效性；结论与「不证明什么」都写在 [docs/experiments/](../../experiments/README.md)。
- **治理文档**：本文件、[SECURITY.md](../../../SECURITY.md)、[CONTRIBUTING.md](../../../CONTRIBUTING.md)。
- **面试材料**：[interview/](../../../interview/README.md)（数据表、20 分钟 walkthrough、简历 bullet）。

## 下一步：先补证据，再加功能

### 1. 把「证据」从草稿变成可复核的

这是最高优先级，因为当前最大的弱点不是功能，而是部分标注仍是作者自拟：

- **独立复核标注**：`evals/judges/` 的 20×3 条 judge 校准样本与
  `evals/attribution/` 的 15 条归因语料目前标为 `author-draft`。找第二个人独立标注，
  重算 κ / 准确率，去掉报表里的 ⚠ 与退出码 1。
- **更长、更接近真实工作的任务**：现有任务最长约十几轮；E1 长任务的保留率已经降到
  83–97%，说明天花板开始出现。下一轮加 20+ 轮任务链，让成功率和保留率真正分层。
- **多模型对照**：当前所有实测都是 `deepseek-flash`。协议槽位已留好，补第二个模型，
  检验结论是否只对单一模型成立。
- **repeat ≥3 + 置信区间**：E1/E4 多为单次或两次重复；成本波动可达约 18%，
  百分比只能读作方向。提高重复次数并报告区间。

### 2. Dogfood 变成连续记录

- 从 2026-10-18 起已有日志脚手架（[docs/dogfood/](../../dogfood/README.md)），
  但记录仍为空。目标：每天至少一条真实任务，记录成本、耗时与翻车点。
- 把 dogfood 中重复出现的问题变成票据；修完后补回归任务。

### 3. 上下文与成本工程

- **缓存关闭的 A/B**：E2 的 80.8% 是反事实重算，不是「关掉缓存再跑」的对照。
  补一轮真实对照，量化确定性前缀的实际收益。
- **off-peak 调度**：现在只是记账时识别峰谷；下一步把非紧急任务排队到低谷执行。
- **预算护栏**：SPEC 里设计了会话/任务级 token 或金额上限，v1 尚未实现；
  加上「触及上限暂停/终止并写轨迹」。
- **压缩模板继续迭代**：三节模板在长任务上已经优于七项模板（93.3% vs 87.8%，
  成本 −23.1%）；继续用 checkpoint 保留率做 A/B，而不是凭感觉改摘要。

### 4. 扩展性

- **MCP 客户端**：v1 明确不做；下一版本优先补，让工具生态不必内建进 minimal core。
- **扩展机制**：内核只保留四工具；其余能力通过扩展/协议组装，并复用同一套权限规则。
- **更多 provider**：协议抽象与目录位置已留；补 `anthropic-messages` 真实适配器、
  端到端验证与跨协议回归测试。

### 5. 沙箱与安全加固

- **网络白名单**：v1 只有 deny-all；补容器内代理与证书信任，让装依赖不必走
  `--no-sandbox`。
- **文件工具工作区围栏**：`read` / `write` / `edit` 目前在宿主机执行、接受绝对路径；
  增加可选的「只在工作区内」模式（见 [SECURITY.md](../../../SECURITY.md) 已知限制 1）。
- **OS 级沙箱后端**：在 Linux 上评估 bubblewrap、macOS 上评估 seatbelt，
  作为 Docker 之外的轻量选项。
- **导出脱敏**：提供可选的 key/token 扫描与脱敏，降低分享会话时的泄露风险。

### 6. 使用体验

- TUI 的压缩点、权限拦截、护栏事件的浏览与过滤。
- `--resume` / `--fork` 的交互改进与更大规模会话的性能验证。
- 成本面板按阶段/工具拆分，支持导出 CSV。

## 明确不做（v1 范围外）

来自 [SPEC.md](SPEC.md) 的 Out of Scope，除非重新立项：

- 多 agent 编排（subagent / agent teams / 并行编排）；
- RAG / 向量检索 / 代码库索引（检索走 agentic grep）；
- 真实接入 Anthropic / OpenAI 生产 API（只留协议抽象与目录槽位）；
- Web UI / IDE 插件 / 桌面端（CLI + TUI + HTML 导出是全部交互面）；
- 云端执行 / 服务化 / 多用户；
- 微调 / 训练 / RL；
- Windows 以外的平台承诺（代码跨平台，但未测试即不承诺）；
- 模型视觉输入 / 多模态。

## 怎么影响优先级

- 开 issue 说明使用场景、复现步骤与期望结果；安全相关问题走私密渠道（见
  [SECURITY.md](../../../SECURITY.md)）。
- 带数据的 issue 优先：一个可复现的失败轨迹 + 会话文件，比功能愿望更有用。
- 超期时的砍单顺序沿用 PLAN.md：E5 → E3 → C 桶任务 → Responses 协议 → TUI 视觉打磨；
  E1/E2/E4 是核心，必须完成。

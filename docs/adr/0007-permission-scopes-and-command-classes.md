# 权限：显式决策、命令类与会话规则

Status: accepted (2026-10-20)

权限层从「规则 + 四档审批」升级为「判定 + 决策 + 作用域」：

- 决策五档：本次 / 本会话 / 始终 / 拒绝 / 手动输入建议。
- 优先级：deny 永远最高；显式批准（本次/本会话/始终产生的规则）覆盖 ask；ask 覆盖 allow；无规则默认 ask。
- 「始终允许」继续写用户级 `~/.codelotte/permissions.json`，不写项目文件；弹层显示将写入的精确规则。修复 subject 含 glob 元字符时持久化未转义的 bug。
- 「本会话」按作用域生效：
  - 文件工具：工作区路径范围；`/workspace/...` 映射到 cwd，相对路径解析，symlink `resolve()` 后判定；越界仍 ask。
  - bash：按 shell segment 分段，每个 segment 必须命中；命令类 = 可执行文件 + 子命令（如 `git status`），不是原始字符串前缀；包装器、命令替换、重定向、全局 flag 位于子命令前等无法静态判定的形态一律 ask；危险 flag（`rm -rf`、`push --force`、`reset --hard` 等）永远重新询问。
  - MCP：按 `mcp__<server>__<tool>` 全名放行，弹层显示 server 名。
- 会话规则在 resume/fork 时从 `permission` 记录重放（`decision=session`），不新增 entry 类型；不跨会话。
- 手动输入建议 = 拒绝该次调用 + 用户文本作为 tool error 回给模型 + run 继续；不计入连续失败熔断。普通拒绝仍计入。
- 一次模型回合的多个 tool call 逐条审批，不提供批量放行。

理由：

- 原始字符串前缀会放行 `git status; rm -rf /`；命令类 + 分段是能同时满足安全与「同类不再问」的最小模型。
- 文件工具在宿主机执行且接受绝对路径；整工具放行等于全盘写权限，路径范围是必要的。
- 用户显式批准却仍被已有 ask 规则压住，是现有实现的体验缺陷；显式批准高于 ask、低于 deny，符合直觉且保留 deny 的绝对性。
- Session 是唯一事实源；会话规则重放让「本会话」在 `--continue` 后仍然成立。
- 反馈是用户纠偏，不是模型失败；计入熔断会让连续纠偏错误地终止 run。

被否备选：

- 原始字符串前缀匹配（可被复合命令绕过）。
- 维持 `deny > ask > allow` 的纯 severity 合并（显式批准无效）。
- 文件工具整工具放行（全盘写权限）。
- 把「始终允许」写进项目配置（自动改写可能被提交的仓库文件）。
- 批量放行或记住整次模型的全部工具调用（审计粒度不足）。

后果：

- 需要 shell 词法分析与命令类提取；无法解析的形态一律 ask，部分常见命令会比现在多问一次。
- 审批弹层增加输入框与命令类展示；测试矩阵扩大。

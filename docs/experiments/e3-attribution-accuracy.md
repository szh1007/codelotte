## 3. 真实失败分布

扫描结果（`evals/runs/` 下全部 `report.json`）：

| 项 | 数量 |
|---|---:|
| codelotte 失败 | **0** |
| 已归因（五类合计） | 0 |
| codelotte 失败但未归因 | 0 |
| 非 codelotte harness 失败 | 23（全部是 raw） |
| 控制 agent 案例跳过 | 42 |
| 压缩回归/非通用测评案例跳过 | 124 |

- **codelotte 全通过**：E4 正式 run 27/27、E4 对照 codelotte 18/18、E5 新增注入
  跑数 15/15、死循环压力 3/3；历史 smoke/judge run 也全部通过。没有失败案例，
  五类分布自然为空。注：死循环压力案例虽然通过，但会话里有 `guardrail` 事件，
  属于“防线介入后模型改法完成”，不是无事件通过。
- **23 条非 codelotte 失败**全部来自裸单轮 API（旧 5 任务对照 5 条 + E4 对照 18 条）。
  它没有工具循环，无法落盘；这是结构下界，不是五类归因的对象，报表里单独计数。
- **控制 agent 与压缩回归不混入**：oracle/no-op/cheating 是评测器自检，压缩回归用
  `completed/checkpoints` 而不是 `passed`；两者都跳过，避免污染“真实 agent 失败”口径。

## 4. 这证明了什么、不证明什么

**证明：**

- 规则按文档工作：五类样本都能被对应规则命中，且没有跨类误判；
- 归因是确定性的、可解释的：每条结论有证据与机器可读信号，不增加模型调用；
- 失败分布工具能正确区分 codelotte / 非 codelotte / 控制组 / 压缩报表。

**不证明：**

- **不证明真实失败上的泛化能力**：15 条语料是作者按五类构造的，规则和样本同源，
  存在天花板效应；标注者仍是 `author-draft`，命令退出码 1。
- **不证明任务集足够难**：已入库 run 里 codelotte 零失败，说明当前任务集把
  “失败”这个变量压到了地板；没有失败，就没有真实分布可谈。
- **不证明五类互斥且完备**：模糊失败仍会落到 `model` 兜底；`context_loss` 用
  “压缩后重读同一文件”作代理，会漏判“没重读但确实丢信息”的情况。

## 6. 复现

```bash
# 只校验语料类别/数量（不跑分类、不写报告）
uv run codelotte eval attribute --dry-run

# 准确率 + 失败分布（离线，不调用模型）
uv run codelotte eval attribute --run evals/runs --out evals/attribution
```

退出码：`0` = 准确率达标且标注已复核；`1` = 准确率低于阈值或标注含 `draft`
（当前就是 1）；`2` = 语料/路径配置错误。

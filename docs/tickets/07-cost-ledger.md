## 实施记录（2026-10-15）

- **价目表数据化**（[models.json](../../src/codelotte/providers/models.json)，随包内置）：**人民币元**峰价表（flash 命中 0.04 / 未命中 2 / 输出 8；v4-pro 0.30 / 9.0 / 27.0，出处：官方定价页 api-docs.deepseek.com/zh-cn/quick_start/pricing，2026-10-16 核对）+ 峰谷窗口 + 节假日表 + `offPeakMultiplier: 0.5`。**谷价不存第二份**：它是"峰价 × 系数"这条规则——数据里存规则，同一个事实只有一个来源。可被 `~/.codelotte/models.json` **整份覆写**（节假日表"可配置"的落实；坏文件以 ConfigError 报出，退出码 2）。账单带货币标识（记录里落 `currency`，导出/审计可追溯——本票刚发生了"误记美元"这一课，见下）。
- **定价更正（2026-10-16，用户指出）**：首版按早期调研笔记记的是美元换算值；官方定价页实际以人民币元计价。全链路已改：`models.json` 换成官方元价目、账单/状态栏按目录货币渲染（`format_money`，¥）、usage 记录字段 `usd` → `cost` + 新增 `currency`（记录自描述）；docs/tech/deepseek-api.md §2 留更正说明与出处链接。教训：**价目这类会变的事实，写进数据文件不够，还要给事实源留链接与核对日期**。
- **时区用固定 +8 而非 tzdata 库**：中国无夏令时，固定偏移是精确的；不为一个时区新增依赖。（2026 全年法定节假日 + 调休上班日已按国办发明电〔2025〕7 号核录；调休周末按 DeepSeek 规则仍算空闲价——规则只说"不含法定节假日"，这处口径写进了 `holidaysNote`，对账时若发现不符由此入手。）
- **判定与计价是纯函数**（[cost.py](../../src/codelotte/cost.py) `Catalog.period_at` / `price_call`）：传时刻即可复算任意一次调用；`period_at` 拒绝 naive datetime（防"按系统时区误解"这一类静默错账）。
- **计价口径的兜底**：provider 没拆缓存时（hit+miss 盖不住 input），差额按**未命中**记——不拆的部分按贵的那档算，估价宁高不低。DeepSeek 实际总会拆（`_parse_usage` 也补过一道），这是防御性口径。
- **落盘与广播**：usage 记录新增 `period`（peak/offpeak）、`cost`（目录里没有该模型则 None——token 照记，不瞎估价）、`requestFingerprint`（sha256 前 16 位，SPEC §I；同一状态两次运行指纹一致、历史一变就变）。事件流新增 `CostRecorded`（loop 层事件）而不是改 Provider 层的 `UsageEvent`——计价是应用层事实，不该污染 provider 抽象；TUI/无头都只消费，不自己算账。
- **账单三组口径一致**：按模型/按时段/按缓存三组金额都**逐次调用按各自时段折算后相加**——不会出现"分类加起来不等于合计"的时段折扣错位。老记录（票据 05 时代无 period/cost）token 照统计、金额置 None，不按今天的价目回溯改账。
- **展示三处**：TUI 状态栏 `tokens in=… out=… 缓存命中… │ ≈$…`（回放历史同一本账）；`-p` 会话结束打印分项账单；数据落会话（票据 08 导出、票据 15/20 实验直接用）。
- **两轴代码审查（Standards / Spec）后的修正**。
  - Spec 轴实测抓到四个账务缺口：
    1. **失败/中断路径不报账**：usage 已落盘但流随后失败时跳过汇总（修：汇总挪进 `finally`，钱花了就得报账）。
    2. **取消丢账**：用量已收到（=已在计费）但流被取消时不落 usage（修：`_record_usage` 抽成一处，取消路径补记）。
    3. **账单三组金额不同源**：合计/按模型用记录 cost、按缓存却拿当前价目重算，改价或老记录会出现“分类加起来不等于总账”（修：分类按计价权重**分摊**记录的 usd，三组之和恒等于合计）。
    4. **口径不一致**：`-p` 账单只含本次运行而 TUI 含整条分支，且 TUI 退出无汇总（修：账单统一为**会话累计**、从记录读，TUI 退出打同一份；tokens 行标注“本次运行”以示区别）。
  - Standards 轴的修正：
    - 计价公式收拢为 `_call_cost` 一处（`price_call` 与账单分摊共用）。
    - 命中率渲染收拢为 `Ledger.hit_rate_text`。
    - 删掉已被 `CostRecorded` 取代却仍在广播的 `UsageEvent`（孤儿事件面）。
    - `AgentLoop` 的 catalog 改为**必填**（原默认值会悄悄读开发者的用户覆写文件，污染测试——测试改用 `fake_catalog`）。
- **审查还暴露一个旧缺陷**（涉及 07 的指纹承诺）：无工具调用的回答**从不进 live messages**——同进程下一轮请求缺上一条回答，与 `--continue` 重建的请求不一致（缓存前缀与请求指纹都错位，"同一状态两次运行指纹一致"因此不成立）。修：答案也进上下文，回归测试 `test_final_answer_enters_context_so_live_and_resumed_requests_match` 钉死 live 与恢复两条路径的请求逐字段一致。
- **测试**：
  - 新增 25 项：cost 16（边界/矩阵/目录加载/覆写/账单渲染/改价分摊/老记录）；loop 3（计价落盘、指纹稳定性、live = 恢复）；TUI 2（实时花费与回放花费）；run 4（失败报账/取消补账/会话累计/空会话不出账）。

## 对账记录（方法与结果）

**方法**（供复现）：
1. 配好真实 `DEEPSEEK_API_KEY`，跑一次有工具调用的真实任务（`codelotte -p "..."`）；
2. 会话文件里每条 `usage` 记录的 `cost` 求和（`jq` 或导出）；同时看 `period` 是否与调用时刻相符；
3. 对照 DeepSeek 开放平台账单页的当日金额与时段明细，记下偏差（预期：与峰/谷判定口径一致时偏差 ≈ 0；若不符，优先核对调休上班周末与"不含法定节假日"的口径）；
4. 注意：价目以官方定价页（api-docs.deepseek.com/zh-cn/quick_start/pricing）为准、2026-10-16 核对；若平台改价需同步 `models.json`（这也是数据化的意义）。

**结果（2026-10-16）**：用户真机执行——本地 `codelotte` 记账（含峰谷判定与缓存两档价）与实际 DeepSeek 账单**一致，无偏差**。验收第 5 项通过。

# 03: Agent 循环 + read 工具

**What to build:** 把"一问一答"升级为"智能体循环"：模型可以请求调用工具（本票先实现 `read`，支持行范围），程序执行后把结果回填给模型，循环继续，直到模型不再请求工具即为回合结束。核心难点：流式响应里工具调用的参数是**分片到达**的（模型是一段一段吐参数的），必须先攒齐再解析为完整 JSON；同一回复可能并发请求多个工具调用，需正确配对。工具执行失败（如文件不存在）不视为系统错误，而是把错误信息作为工具结果回传给模型让它自纠。

🗣 大白话：装上"循环大脑"和第一只手——它开始自己决定"我先读读那个文件看看"，读完再决定下一步。

## 实施记录（2026-10-14）

- 真机验收：`codelotte -p "读一下 CONTEXT.md 并告诉我第一行"` → 模型自主调用 `read({"path":"CONTEXT.md","limit":1})`，答出首行 `# codelotte`，exit 0；stdout 只有答案（工具活动在 stderr）。README.md 尚未创建（票据 14），故以 CONTEXT.md 代替。
- 真机会话第二轮 `cacheHitTokens=384`：assistant 的 `reasoning_content` 与原始参数 JSON 文本逐字节回传，前缀缓存按设计命中。
- 测试：82 项全绿（新增装配器 11、read 工具 15、provider 7、端到端 5）；ruff / pyright 均通过。
- 两轴代码审查（Standards / Spec）后修正：工具事件严格「先落盘再呈现」（SPEC §E）；畸形参数不再中止回合，改为 `parseError` 记入会话并作为工具结果回传（一个坏调用不拖垮并行的好调用，SPEC §D）；模型漏 id 时的合成 id 带随机后缀（避免多轮 `tool_call_id` 撞车）；read 的畸形整数参数改为报错而非静默回退；删除无调用方的 `tools=` 形参；**管道纯净**（见下）。

### 行为决定

- **迭代上限触发 → exit code 1**：回合被程序强制结束，不算正常完成（与流被截断同等对待）。会话中落 `event`（kind=iterationLimit）。
- **文本去向按 stdout 是否 tty 分流**：真终端实时流式输出（人要看到进度）；管道/重定向时不实时写，轮末决定——终轮文本（答案）进 stdout，中间轮次的过渡叙述进 stderr。真机实测：模型确实会在 content 里写 "I'll read the first 3 lines…" 这类叙述，若不分流会污染管道。

### 有意延后（记入后续票据）

# 06: 会话树与分支 / fork

**What to build:** 把会话记录从线性升级为"树"：每条记录携带 id 与 parentId；上下文装配时沿"活动分支"从根回溯重建，天然支持分支。新增能力：`--continue` 恢复上次活动分支、`--resume` 选择历史会话、`fork` 从任意历史点创建新分支（两条分支互不干扰，各自可继续）。同时确立**确定性序列化**：同一分支两次装配出的请求前缀必须逐字节一致——这是命中模型缓存（价格差约 50 倍）与结果可复现的前提。

🗣 大白话：对话记录变成一棵树——可以从过去任何一刻"分岔"，同一个任务试两种方案互不影响；而且因为记录方式稳定，模型能认得出"这段我见过"，重复内容按极低价计费。

## 实施记录（2026-10-15）

- **单文件树，零 schema 变更**。票据 01 起每条记录就带 `id/parentId`（当时就按树的字段写的），本票把"树"真正用起来：线性对话＝退化的单链，fork＝在**同一文件内**从某条历史记录分岔——原分支记录一字不动（append-only 不变量保持），新记录挂到分岔点之下。依据 ADR-0003「分支/fork/compaction 都在同一模型里」——票据 08（HTML 导出）与 12（压缩）都在这棵树上继续盖。
- **fork 写一条 `event/kind=fork` 标记**（[store.py](../../src/codelotte/session/store.py) `SessionStore.fork`）。理由：「记录是事实源」——fork 这个动作本身要落盘，这样 fork 后哪怕一句话没说，`--continue` 也已经落回新分支（否则下次恢复会悄悄回到老分支，用户会懵）。**活动分支＝文件最后一条记录所在的 parentId 链**：谁最后说话，`--continue` 就回到谁。
- **旧文件兼容策略＝不迁移**：v1 起每条记录都有 id/parentId，旧线性文件的回溯结果与文件顺序逐条相同（`test_branch_entries_linear_is_file_order` 为证）。链断裂 / parentId 成环 / 叶子不存在直接报错——损坏的会话不该被猜着读。
- **CLI**（[cli.py](../../src/codelotte/cli.py)）：`--continue`（原样，语义升级为"活动分支"）；`--resume [序号]`——不带序号列出**叶子**清单（每个叶子＝一条可继续的分支，带 `⎇ 分支（fork 于 …）` 标注与活动时间排序），带序号恢复指定分支；`--fork N` 从活动分支倒数第 N 条消息处分岔（N=1 即最后一条，`--fork 2` 最常用：重答倒数第二问），**可与 `--resume <序号>` 组合**（`--resume 2 --fork 1`＝在第 2 条分支上分岔）——"任意历史点"因此覆盖任意会话的任意分支。列表是只读查询：**不需要密钥**、不建会话文件。
- **`--resume` 是导航，不落盘**（有意的不对称，审查后明确）：它只把后续记录的挂点切到所选分支——说了话才产生记录；没说话就退出，`--continue` 仍回到"最后有记录的地方"。fork 之所以写标记，是因为它**创建了一个新分支**（创建本身就是记录，也让"fork 完没说话就退出"不会迷路）。同一个原则，两种表现。
- **确定性序列化**（缓存前提）：装配路径没变（`messages_from_entries` 纯函数），树只改变"喂进去的记录序列"。两个测试钉死：① 同一状态两次装配逐字节一致；② 分叉不改前缀——新分支与原分支在分岔点前逐字节相同（DeepSeek 前缀缓存命中率的直接保障）。
- **顺带修一个真缺口**：TUI 的 `--continue` 回放原来读**整份文件**——分叉后会把其它分支的记录也画出来。改为只回放活动分支（`_run_tui` 按 `loop.leaf_id` 取 `load_branch`，回归测试 `test_build_agent_history_follows_selected_branch` 钉死）。
- **两轴代码审查（Standards / Spec）后的修正**。Spec 轴实测抓到两个可复现的 CLI 硬伤：① **一个损坏文件打死整个 `--resume`**（连"选有效会话"都会被无关坏文件牵连）——改为逐文件/逐叶子隔离：坏的跳过、`--resume` 列表把"警告：跳过损坏的会话——…"打给用户（不静默吞）；② **`-p X --resume`（无序号）静默丢弃提示词**——改为显式用法错误。另补一处能力缺口：`--resume <序号> --fork N` 组合，让"从任意历史点分岔"覆盖任意分支。Standards 轴的修正：base-dir 默认值第三处重复抽成 `_default_base_dir()`；`load_entries+branch_entries` 的组合形态收拢为 `load_branch()`；`open_at` 不再绕过公开 API 改私有字段（`SessionStore.resume(leaf_id=…)`）；CLI 错误分类用新的 `SessionError`（不再把 json 解码之类的 ValueError 一并吞成用法错误）。回归测试 7 项（坏文件隔离 ×2、提示词丢弃、组合分岔、用法错误 ×2 等）。
- 测试：新增 23 项（树/分叉/列表 12、CLI 10 含回归、e2e 扩展）。端到端 `test_fork_and_resume_keep_two_branches_independent` 用真实子进程跑通"线性 → fork → 两条分支各自 --continue/--resume → 组合再分岔"全流程并断言双方互不污染。全套 185 项全绿；ruff / pyright 干净。

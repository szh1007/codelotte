AI / Agent 后端一页纸

把 Redis / Kafka 映射到你的项目，并准备好“没用过生产中间件”的诚实说法。 面试前 5 分钟翻这一页即可。

1. 先记住三个不同

维度电商高并发AI/Agent 后端
请求耗时几十–几百 ms几秒–几十秒，流式
瓶颈DB 写、热点读LLM 配额、token 成本、外部 API
并发手段线程/连接池asyncio + 多 worker + 队列
一句话

LLM 调用是 I/O 密集型；Python 的 GIL 限制 CPU 并行，不影响“等待时切走”。

2. 中间件映射

需求组件用法追问
会话/上下文Redissession:{id} 存最近上下文，TTL一致性、隐私、租户隔离
精确响应缓存Rediskey 含模型/参数/租户，exact-match命中率、失效
租户限流/配额Redis + Lua令牌桶，按 tenant/user 扣突发、热点、故障降级
预算/并发锁Redis SET NX PX防重复执行、控并发锁正确性、fencing
长任务/评测Kafka/RabbitMQ异步执行，状态写 Redis/DB重复、顺序、积压、死信
工具/审计事件Kafka按 session 分区，可重放不丢、顺序、保留
用量计费Kafkausage 事件异步聚合重复计费、对账
失败重试RabbitMQ DLX / RocketMQ延迟重试，超限死信重试风暴、幂等
边界

Kafka 不做请求-响应；实时回答走 HTTP/SSE，异步副作用走 MQ。

3. “10 万用户”答题骨架

  1. 量化：在线 ≠ QPS；估活跃请求、LLM 调用频率、token 成本。
  2. 入口：鉴权 + Redis 租户令牌桶 + 配额，超限 429。
  3. 应用：FastAPI/uvicorn 多 worker，asyncio + 异步客户端连接池，超时/取消。
  4. 缓存：会话/精确响应；语义缓存加租户隔离和阈值。
  5. 异步：Kafka 长任务/审计/用量；消费者幂等，失败死信。
  6. 保护：LLM 熔断 + 备用模型 + 队列背压 + 成本预算。
  7. 观测：TTFT、tokens/s、成本、错误率、队列 lag。

4. 诚实说法（可直接背）

“我在 codelotte 里没有生产级 Redis/Kafka 使用。为了回答这类问题，我做了两件事： 一是按 Agent 的业务链路设计了缓存、限流和异步任务方案； 二是在本地用 Docker 跑了 Redis 缓存和 Kafka 生产消费的最小实验。 所以我能讲清楚设计和取舍，但不会声称我有大规模生产运维经验。”

5. 30 分钟本地实验

docker run -d --name hc-redis -p 6379:6379 redis:7-alpine
docker exec -it hc-redis redis-cli ping

docker run -d --name hc-kafka -p 9092:9092 apache/kafka:4.4.0

docker exec -it hc-kafka /opt/kafka/bin/kafka-topics.sh \
  --create --topic demo --bootstrap-server localhost:9092
docker exec -it hc-kafka /opt/kafka/bin/kafka-console-producer.sh \
  --topic demo --bootstrap-server localhost:9092
docker exec -it hc-kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --topic demo --bootstrap-server localhost:9092 --from-beginning

Python 侧：pip install redis confluent-kafka，先跑 Redis 的 SET/GET， 再用 confluent-kafka 发一条消息、消费一条。能说“本地跑过”即可，不夸大成生产集群。

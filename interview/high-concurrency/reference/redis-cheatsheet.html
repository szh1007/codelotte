1. 什么时候用 / 不用

适合不适合
读多写少、可接受短暂旧数据的缓存 强一致、不能丢的唯一数据源
计数器、排行榜、去重、签到、UV 大 value、大集合、复杂事务查询
分布式锁（效率型）、限流、会话 需要跨 key 强事务、复杂 join
轻量队列（Stream） 海量消息长期保留、流处理（用 Kafka）
一句话

Redis 是“内存里的高速数据结构服务”，不是“免费的数据库”。

3. 缓存模式与三大问题

读：GET cache → miss → 查 DB → SET cache (TTL)
写：UPDATE DB → DEL cache（不是更新缓存）
问题现象解法代价
穿透 key 在缓存和 DB 都不存在，每次打 DB 空值缓存、布隆过滤器、参数校验、限流 空值占内存；布隆有假阳性
击穿 单个热 key 过期，大量并发回源 互斥重建、逻辑过期、永不过期+后台刷新、请求合并 延迟/旧值/实现复杂
雪崩 大量 key 同时失效或 Redis 整体挂 TTL 抖动、多级缓存、Sentinel/Cluster、限流降级、预热 成本、一致性、降级体验

4. 缓存一致性

  • 能接受秒级旧数据：cache-aside + 更新 DB 后删缓存 + TTL 兜底。
  • 并发回填旧值：延迟双删；更稳的是订阅 binlog（Canal/Debezium）发 MQ 删缓存；value 带版本号。
  • 读己之写：写后短时间读主库，或写后主动删缓存并处理回填。
  • 强一致：缓存不承担正确性；用 DB 事务、唯一约束、乐观锁/悲观锁。
竞态：读 A miss → 读 DB 旧值 V1 → 写 B 更新 DB V2 + 删缓存
      → 读 A 回填 V1 → 缓存长期旧值
应对：延迟双删 / binlog 删缓存 / 版本号 / TTL 上限

5. 持久化与高可用

能力方案要点
快照RDBfork + COW；恢复快；可能丢最后一次快照后的数据
日志AOFfsync always/everysec/no；everysec 最多约丢 1 秒
兼顾混合持久化 / multi-part AOFRDB 头 + 增量命令；恢复更快
读扩展主从复制默认异步；从节点可能旧；WAIT 也不是强一致
自动切换Sentinel监控 + 投票 + 提升从节点；不分片；至少 3 个
分片 + 切换Cluster16384 slots；MOVED/ASK；多 key 要同槽
高频追问

“主从是同步还是异步？”——默认异步。“Sentinel 和 Cluster 区别？”——前者只做高可用，后者分片 + 高可用。

6. 分布式锁

import redis, uuid
r = redis.Redis()
key, token = "lock:order:1", uuid.uuid4().hex

ok = r.set(key, token, nx=True, px=30_000)
if ok:
    try:
        do_work()
    finally:
        r.eval("""
        if redis.call('get', KEYS[1]) == ARGV[1] then
            return redis.call('del', KEYS[1])
        end
        return 0
        """, 1, key, token)
  • 必须 SET NX PX 一条命令；不要 SETNX 后再 EXPIRE。
  • 解锁必须比较 token + Lua 原子删除；不能直接 DEL。
  • 长任务用 watchdog 续期；续期也有边界。
  • Redlock 有时钟/暂停争议；正确性场景用 DB 约束/乐观锁或 fencing token。

7. 限流

算法特点适合
固定窗口简单；边界可能双倍粗粒度、容忍误差
滑动窗口日志精确；内存随请求增长低 QPS、精确
滑动窗口计数近似、省内存通用 API 限流
令牌桶允许突发租户/用户限流、LLM 配额
漏桶平滑输出保护下游、队列

分布式限流用 Redis + Lua 原子扣减；返回 429 + Retry-After；网关粗粒度 + 应用细粒度 + 本地桶兜底。

8. 热 key / big key / 淘汰

  • 热 key：本地缓存、拆 key、读副本、请求合并、限流。
  • big key：String > 10KB 或集合 > 5000 元素要警惕；拆分、UNLINK、压缩、TTL、--bigkeys 扫描。
  • 淘汰：noeviction、allkeys-lru/lfu、volatile-lru/lfu/ttl/random；淘汰是兜底，不是容量规划。
  • TTL：所有缓存 key 都要有；加随机抖动，避免集体过期。

10. 面试一句话

Redis 为什么快？
纯内存、IO 多路复用、命令单线程无锁、紧凑编码；瓶颈在网络/CPU/大 key。
单线程怎么高并发？
单线程指命令执行；epoll 管连接，命令串行避免锁；多实例/Cluster 扩核。
缓存穿透/击穿/雪崩？
不存在的 key / 单热 key 过期 / 大面积失效；空值+布隆 / 互斥+逻辑过期 / TTL 抖动+多级+限流。
缓存一致性？
先问要求；常规 cache-aside + 更新 DB 后删缓存 + TTL；并发用延迟双删/binlog；强一致不靠缓存。
RDB vs AOF？
RDB 快恢复、可能丢一段；AOF 更安全、恢复慢；按 RPO 选，常用混合。
Sentinel vs Cluster？
Sentinel 只做故障切换；Cluster 分片 16384 slots + 故障切换。
分布式锁怎么写？
SET NX PX + 唯一 token + Lua 比较删除 + 续期；正确性用 DB 约束/fencing。
限流怎么选？
允许突发用令牌桶，平滑用漏桶，简单用固定/滑动窗口；分布式用 Redis Lua。
热 key / big key？
热 key 本地缓存/拆分/读副本；big key 拆分/UNLINK/压缩/扫描。
Redis 挂了怎么办？
Sentinel/Cluster 切换；本地缓存+限流降级；恢复后预热+对账；按 RPO 选持久化。

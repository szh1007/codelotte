# Mission: 高并发后端中间件面试（Redis / Kafka / MQ）

## Why

你正在密集面试 **AI/Agent 后端（Python）** 岗位，几乎每天都有面试。项目、Python、Agent 部分你能讲，但一被问到 Redis、Kafka/MQ 的高并发应用场景就“没货说”。这个工作区的目标不是把你变成中间件运维专家，而是让你在面试里**能开口、能讲原理、能落到场景、能接住追问**。

## Success looks like

- 任意高并发题，60 秒内能用“量化 → 找瓶颈 → 三板斧 → 兜底”四层骨架开口，而不是沉默或堆名词。
- 能讲清 Redis 的缓存模式、穿透/击穿/雪崩、持久化、主从/Sentinel/Cluster、分布式锁、限流算法，以及各自的取舍。
- 能讲清 Kafka 的分区/副本/ISR/消费者组、三种投递语义、消息不丢/不重/有序/积压的处理方式，并能对比 RabbitMQ、RocketMQ。
- 能独立设计并口述课程中的 12 个经典场景，至少覆盖秒杀库存、订单超时、缓存一致性、排行榜、接口限流、消息积压、重复消费、大促削峰。
- 能把 Redis/Kafka 映射到自己的 Agent 项目（会话缓存、租户限流、任务队列、用量事件），并**诚实说明**哪些是设计、哪些是实测。
- 完成 10 道模拟追问，按 4 分制自评 ≥ 3 分；被追问“为什么不用另一个方案”时能说出取舍。

## Constraints

- 每天都有面试，学习时间碎片化；课程按 **20–30 分钟一课**设计，但允许一次性通读。
- 目前 **没有 Redis / Kafka 的实际使用经验**；先建立直觉和答题框架，再补命令与实验。
- 技术栈是 **Python**；示例优先用 Python / redis-py / confluent-kafka，不陷入 Java 生态八股。
- 讲解偏好：中文、大白话、结论先行；先给面试可用的说法，再补原理。
- 不能编造生产经验；项目里没有的，就用“我设计过 / 我本地验证过 / 我理解它的取舍”来表达。

## Out of scope

- Java 八股（JVM、Spring、GC 调优）与 Java 客户端生态。
- Kubernetes / Service Mesh / 云原生网络细节。
- Redis / Kafka 源码级剖析、内核参数调优。
- 分库分表中间件（ShardingSphere）、Flink/Spark 等大数据生态。
- 把每个中间件讲成产品全貌；只覆盖面试高频、能支撑场景设计的部分。

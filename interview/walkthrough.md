## 4. 6:00–11:30 现场演示

### 4.1 现场跑一次真实任务（6:00–9:00）

**屏幕：** 终端，`docs/demo/sample`。

```bash
cd docs/demo/sample
uv run codelotte -p "Fix the off-by-one bug in calc.py. First read calc.py and check.py. Then use edit to change the loop so it sums exactly the first n elements. Run 'python check.py' to confirm it passes. Then create notes.txt containing exactly the text 'for i in range(n):' followed by one newline (no indentation). Do not modify check.py." \
  --allow read --allow edit --allow write --allow 'bash(python check.py)'
```

**边跑边说（按出现顺序）：**

1. **`read` 两次**：模型先看 `calc.py` 和 `check.py`，不是盲改。
2. **`edit`**：参数是精确替换；工具在宿主机工作区执行。
3. **`bash python check.py`**：默认在 Docker 容器里跑，网络 deny-all；
   只有这条精确规则被放行。
4. **`write notes.txt`**：精确内容验收。
5. **最后一条组合命令被拒绝**：`cd . && od -c ... && git diff ...` 没匹配到显式规则，
   无头模式 fail-closed，模型改用 `read` 验证。**这是权限层真实工作的证据，不是失败。**
6. **成本行**：7 次模型调用、缓存命中率、本次约 ¥0.0096（峰值时段）。

**实测参考（2026-10-19，本机 Windows + Docker）：**

| 指标 | 实测 |
|---|---|
| 墙钟耗时 | **12.3s** |
| 模型调用 | 7 |
| 本次成本 | ¥0.009622（峰值时段） |
| 缓存命中率 | 87% |

> 注：README 里的样例是低谷时段（¥0.004394，约 9 秒，86%）；同一任务在峰值时段
> 正好约 2 倍。这个差异本身就是 E2 的讲解素材。

## 5. 11:30–16:30 代码走读

**原则：** 只讲五个决策，每个 1 分钟；不要逐个文件念。

### 5.1 会话是数据地基（11:30–12:30）

**打开：** [session/store.py](../src/codelotte/session/store.py#L270)、
[session/context.py](../src/codelotte/session/context.py#L29)。

**说：**

> 「所有东西都是 append-only JSONL 树里的一条 entry：消息、工具调用、usage、压缩、
> 权限判定、护栏事件。entry 带 id/parentId，分支就是树；上下文从活动分支确定性重建。
>
> 这带来三个好处：回放、记账、评测共用同一份数据源；压缩本身也是一条 entry，
> 所以压缩前后可以精确比对；fork/A-B 不需要另一套存储。」

**指：** `SessionStore.append`、`messages_from_entries` 的确定性序列化。

### 5.2 循环与护栏（12:30–13:30）

**打开：** [loop.py](../src/codelotte/loop.py#L249)、
[guardrails.py](../src/codelotte/guardrails.py#L184)。

**说：**

> 「循环只做三件事：请求模型、执行工具、把结果回填。每个阶段发事件，
> TUI、无头模式、评测器消费同一组事件。
>
> 死循环防御是独立的状态机，三层：工具层看重复和无进展；推理层看连续失败；
> 规划层重注入目标与硬约束，必要时温和终止。阈值在 settings.json，事件落会话，
> 导出可见。它不碰网络、不碰会话，所以可以用脚本化 Provider 做确定性测试。」

### 5.3 权限与沙箱（13:30–14:30）

**打开：** [permissions.py](../src/codelotte/permissions.py#L269)、
[sandbox/docker.py](../src/codelotte/sandbox/docker.py#L71)。

**说：**

> 「两层独立：权限层决定『是否允许』，沙箱层限制『实际后果』。
> 权限规则是 `tool(pattern)`，deny > ask > allow，无命中默认 ask；
> 破坏性动词不能被通配规则或裸工具规则放行；项目级规则在 `codelotte trust` 之前忽略；
> 无头模式 fail-closed。沙箱是每会话一个 Docker 长驻容器，只挂工作区，网络 deny-all，
> 有 CPU/内存/超时限额。
>
> 注意一个诚实的限制：`read/write/edit` 在宿主机执行，不受 Docker 约束，
> 由权限层管；Docker 只包 `bash`。这在 SECURITY.md 的已知限制里写明了。」

### 5.4 压缩（14:30–15:30）

**打开：** [compaction/trigger.py](../src/codelotte/compaction/trigger.py#L178)、
[compaction/summarize.py](../src/codelotte/compaction/summarize.py#L56)。

**说：**

> 「双触发：软阈值约 60%，在任务边界压；硬阈值约 85%，立即压到最小保留集。
> 任务边界是用户消息 ∪ 成功 git commit 的 assistant 位置。
>
> 摘要是结构化模板；硬约束不交给摘要器，而是作为独立 system 段重新注入，
> 防止摘要过程把『不许做什么』润色掉。压缩只影响后续上下文装配，原始 entry 仍在，
> 所以可恢复、可审计。」

### 5.5 评测系统（15:30–16:30）

**打开：** [evals/runner.py](../src/codelotte/evals/runner.py#L221)、

**说：**

### 6.2 防御的边界（17:30–18:30）

**说：**

> 「E5 里死循环剧本 5/5、真实模型压力 3/3、正常任务误报 0/31、注入 27/27。
> 这些数字都达标，但边界要说清楚：死循环剧本是脚本化模型行为；真实压力只有 1 条任务、
> 3 次重复；注入是模型行为测试，不是运行时过滤器，只覆盖 5 条自建任务。
> 权限层和沙箱层才是兜底，不能把 27/27 说成『防住所有注入』。」

### 6.3 最难的 bug 与下一步（18:30–20:00）

**说（最难的 bug，二选一讲深）：**

> 「最难的一类 bug 是**边界语义**。比如 Docker 模式下，模型看到的工作区是 `/workspace`，
> 但 `read/write/edit` 在宿主机执行；模型把 `/workspace/foo.txt` 传给文件工具时，
> 它会写到宿主工作区之外。修复是在文件工具里把 `/workspace/...` 映射回宿主 cwd。
> 这个 bug 不是逻辑错误，是两层执行环境的路径语义不一致；只有真实跑 Docker 才会暴露。
>
> 另一个是 Windows 的 MAX_PATH：嵌套评测 run 的会话目录把完整工作区绝对路径编码进目录名，
> 超过 260 字符；后来 eval 会话改用短案例名目录。」

**说（下一步）：**

> 「如果继续做，优先级是补证据而不是加功能：独立复核 judge/归因标注、加长任务链、
> 多模型、repeat ≥3 和置信区间；然后是 dogfood 连续记录、缓存关闭的真实 A/B、
> off-peak 调度、MCP 客户端和网络白名单。这些在 ROADMAP 里。」

**收尾：**

> 「一句话总结：这个项目的价值不是『我写了一个 agent』，而是我有一套能反复回答
> 『改了什么、好了多少、为什么、以及这个结论不能说明什么』的流程。
> 代码、任务集、基线轨迹和复现命令都在仓库里。」

## 7. 附录 A：可能追问与答案

### Q1. 这个系统怎么证明有效？

**答：** 三层证据：① 控制 agent 自检（oracle 9/9、no-op 0/9、cheating 0/9 且全标记）
先证明评测器可信；② E4 同模型三组对照（codelotte 18/18、mini 18/18、裸 API 0/18）；
③ E1/E2 的干预有成本和保留率的分母与反事实。每份报告都写「不证明什么」。

### Q2. 成功率 100%，是不是任务太简单？

**答：** 是，任务集有天花板。9 条任务 × 3 次全过，说明任务把失败压到了地板；
E1 长任务的保留率已经降到 83–97%，说明加长后指标开始分层。
下一步是 20+ 轮任务链和多模型，而不是继续加同量级任务。

### Q3. 和 mini-swe-agent 成功率打平，为什么还说自己做得好？

**答：** 我不说「更好」。成功率是打平；差异是成本–时延取舍：codelotte 贵 15.4%、
调用多 26.3%，但快 33.5%，而且多一层 Docker 开销。
我的价值主张是可观测性和可测量性，不是性能碾压。

### Q4. 压缩后失忆怎么办？

**答：** 三个机制：结构化摘要（任务目标/已完成/决策/约束/文件/下一步）；
硬约束不交给摘要器，作为独立 system 段重注入；压缩后 checkpoint 探针做确定性评分。
E1 长任务保留率 93.3%，但不是无损；原始 entry 仍在会话里，可恢复、可审计。

### Q5. prompt injection 怎么防？

**答：** 两层：权限层（规则 + 破坏性动词保护 + trust + fail-closed）和沙箱层
（只挂工作区、网络 deny-all）。注入任务的 27/27 是模型行为测试，不是运行时过滤器；
真正的兜底是权限和沙箱，所以我在报告里明确写了覆盖范围。

### Q6. 死循环怎么处理？

**答：** 三层独立状态机：工具层重复/无进展拦截；推理层连续失败熔断；
规划层重注入目标与硬约束、必要时温和终止。阈值可配，事件落会话。
剧本 5/5，真实模型压力 3/3 介入且任务仍完成，正常任务误报 0/31。

### Q7. 成本怎么降的？缓存为什么能命中？

**答：** 两个杠杆：确定性序列化让前缀稳定，缓存命中率 89.0%；
峰谷价记账，所有实际调用都在低谷。相对无缓存 + 全峰价，总成本省 80.8%。
但这是反事实重算，不是关缓存重跑；缓存贡献约 62%，off-peak 贡献 50%，
对基准不同，不能直接相加。

### Q8. 归因准确率 100% 可信吗？

**答：** 不完全可信。语料是 `author-draft`，按五类各 3 条构造，规则和样本同源，
有天花板；真实跑数里 codelotte 失败 0 条，没有真实分布。
报表标 ⚠、命令退出码 1；独立复核后重算才算泛化结论。

### Q9. judge κ=1.0 可信吗？

**答：** 同样有天花板。3 个任务各 20 条样本，样本刻意清晰，κ=1.0；
标注是作者草稿。下一步是独立标注 + borderline 样本，再看 κ 是否还高。

### Q10. 为什么自己写 adapter，不用 SDK / LangChain？

**答：** 这个项目的工程对象就是 harness。自写 adapter 才能控制流式解析、tool_calls
装配、usage/缓存字段和 wire protocol 抽象。当前实现并实测的是 `openai-completions`；
`anthropic-messages` 只留了协议位置，未实现——这一点我会主动说，不把计划当成果。
框架会把这些藏在抽象后面，也不利于证明「我真的理解协议」。ADR-0004 有决策记录。

### Q11. 为什么 Python 不用 TypeScript？

**答：** 目标岗位偏 Agent 平台/后端，Python 是主流；Textual 在 Windows 终端有成熟支持，
能规避 prompt_toolkit 系的事件循环问题。ADR-0002 记录了取舍。

### Q12. Docker 沙箱真的安全吗？文件工具呢？

**答：** Docker 只包 `bash`：工作区 RW 挂载、家目录不挂、网络 deny-all、资源限额。
`read/write/edit` 在宿主机执行，不受 Docker 约束，由权限层管（默认 ask，
无头 fail-closed）。这是已知限制，写在 SECURITY.md 里；不是多租户隔离，
也不替代生产级沙箱。

### Q13. 评测怎么防作弊、保证可复现？

**答：** 控制 agent 三关（oracle/no-op/cheating）；cheating 9/9 被标记；
任务锁 git ref/初始文件，案例锁种子、模型、峰谷时段与依赖版本；
每个 run 落 report.md/json + sessions + workspaces；已入库 run 不修改，修正新增一轮。

### Q14. 最难的 bug 是什么？

**答：** Docker 模式下 `/workspace` 与宿主 cwd 的路径语义不一致：模型把
`/workspace/foo` 传给在宿主机执行的文件工具，会写到工作区外。修复是文件工具做路径映射。
另一个是 Windows MAX_PATH：嵌套 eval run 把完整绝对路径编码进会话目录名，超过 260 字符；
改用短案例名目录。这类 bug 只有真实跑才会暴露。

### Q15. 如果给你更多时间，做什么？

**答：** 先补证据：独立复核 judge/归因标注、20+ 轮长任务、多模型、repeat ≥3 与置信区间；
再做 dogfood 连续记录、缓存关闭的真实 A/B、off-peak 调度、预算护栏；
最后是 MCP、网络白名单、文件工具工作区围栏。见 ROADMAP.md。

### Q16. stars 只有 1、也没有 dogfood，怎么解释？

**答：** 诚实说：这是一个 6 天内从 0 做起的求职作品，不是社区项目；stars 不是我的指标。
dogfood 日志脚手架已就位，但连续记录还没开始，所以我没有把它写进成果。
我用可复现的实验和「不证明什么」来代替热度背书。
